feat(tts): 方案 A（点击才生成）+ 固定 seed 确定性流式朗读

按确认的方案实施：播放语义 = 点击才生成；重复点击 = 固定 seed 可复现。

【Python / MemoryServerTTS】
- model_loader.generate_stream 增加 seed 参数：
  - 缺省时按 (文本,音色,语言,指令) 派生**固定 seed**（新增 _derive_seed）
  - 底层流式 API 无 seed 支持，且**不能只用 torch.manual_seed**：
    CUDA Graph 重放会影响全局 CUDA RNG，实测同文本两次结果不同
  - 改为构造独立 torch.Generator（设备与 logits 一致，cuda 张量只接受 cuda generator）
- router /synthesize-stream 接受可选 seed 字段并透传

【backport 补丁（.backport，均为可选参数，默认行为不变）】
- sampling.sample_logits 增加 generator 参数
- streaming.fast_generate_streaming 增加 generator 参数并用于 2 处采样
- model.generate_custom_voice_streaming 增加 generator 参数并透传

【Java / MemoryServer】
- TTSService/Impl 增加 streamSpeechTo(..., Long seed) 重载；
  新增流式专用 buildTTSRequestJson（不带 output_format，带 seed）
- TTSController /synthesize-stream 接受可选 seed
- **ConversationController：客户端发 TTS-Stream:1 时跳过后台 TTS 预生成**
  （避免无人消费的 GPU 生成，也避免给出 audioUrl 让客户端误走"下载后播放"），
  done 事件的 audioPending 相应置 false；老客户端不发此头，行为不变

【Android / Memory】
- 适配器：朗读按钮改为三态（等首片转圈 / 播放中可停止 / 可点击朗读），
  新增 AudioActionListener；新增 ic_stop_24 图标
- Activity：startStreamingTts(msg) / stopStreamingTts(msg)，
  点击才请求流式端点（PcmStreamPlayer + AudioTrack），再点即停；
  onDestroy、发新消息、手动点播放时都会打断；切换目标时释放 MediaPlayer
- AiMessage 增加 audioPlaying 状态
- 新消息发送时带 TTS-Stream:1 头
- 真机联调便利：ApiConstants 增加 LOCAL 环境（adb reverse tcp:8080），
  network_security_config 放行 localhost/127.0.0.1；默认环境仍为 TEST 未改

【实测（真机 HUAWEI HLK-AL00 + 全链路）】
- 首声 501–707ms（服务端自报 447–573ms），播放完成 9.1–9.8s
- Java 日志确认跳过预生成：clientStreamsTts=true / 跳过后台 TTS 预生成
- 确定性：同文本两次波形相关性 0.99999、长度一致；不同文本相关性 -0.0007
  （Predictor 的 15 个 codebook 采样在图内执行，无法注入 generator，
   残差为约 -70dB 数值噪声，听感等同一致）

- bench/verify_stream_determinism.py 确定性校验（按相关性判定口径）
- bench/quantify_determinism.py    量化重复生成差异
